# Tenable open-source automation review for the Qualys-to-Tenable migration

Review date: 2026-11-14. Read-only research. Nothing was installed, run or connected to a Tenable tenant.

## 1. One-line answer

**Only pyTenable is production grade. The CyberAgents Exchange is a source of ideas and reference lists, not deployable tooling, and nothing in any source converts Qualys option profiles, authentication records or SWCA into Tenable.**

What that rests on:

- **146** Exchange listings reviewed: **4 use, 46 maybe, 96 ignore**.
- All 4 "use" items are reference material or a read-only script. None is a platform component.
- **142 of 146** listings are "Contributed" (baseline check only). The **4 "Vetted"** listings are all irrelevant to this migration.
- Every Exchange listing lives in a personal GitHub account. Tenable employees wrote many of them, but **none is a Tenable-supported product**.
- **27** listings can change things in Tenable (launch scans, tag, delete agents, edit policies).

### Decision needed from you first

**Is the target Tenable Vulnerability Management (SaaS), Security Center (on-prem), or both?** This changes the answer more than anything else:

- Hexa AI MCP, navi, Data Stream and roughly three quarters of the relevant Exchange listings are **SaaS only**.
- If the bank lands on Security Center, the usable list shrinks to pyTenable, Tenable Scan Sweep and a handful of Security Center scripts.

**Likely to be skimmed past:** if by SWCA you mean Qualys Software Composition Analysis (open-source libraries found inside applications), the software-enumeration plugins above are **not** equivalent. They list installed packages, not embedded libraries. Nothing in these sources addresses that. Raise it with Tenable directly.

## 4. Tenable Hexa AI MCP

Source: Tenable documentation, read 2026-11-14.

- **What it is:** a Tenable-hosted endpoint (`https://cloud.tenable.com/mcp/`) that lets an AI client such as Claude or Copilot call Tenable tools. Tenable supplies tools and data. You supply the AI model.
- **Licence:** needs **Tenable One Foundation or Advanced**. Not supported in FedRAMP Moderate.
- **Products:** Tenable VM SaaS / Tenable One only. **Not Security Center.**
- **Tool count:** documentation says **90**. One listing author measured **95** on a live tenant on 2026-08-06. Tenable publishes no full tool list or change log.
- **Authentication:** your normal Tenable API keys in a header. Actions run with that user's role.
- **Read-only vs write:** it is **not** read-only.

| Key role | What the AI client can do |
|---|---|
| Read | Search assets, findings, scan results, dashboards, plugins, reports |
| Write | Read, plus launch scans, tag assets, add dashboard widgets, change scan schedules |
| Manage | Write, plus create and delete scans, dashboards, policies, tags, reports; configure scan policies and agent settings |

- **Tool names seen in listings** (not a complete list): `tenable_one_search_assets`, `tenable_one_search_findings`, `tenable_one_search_software`, `workbenches_list_vulnerabilities`, `workbenches_get_vulnerability_outputs`, `scan_list_scans`, `scan_results`, `scan_create`, `scan_configure`, `scan_launch`, `policy_create`, `policy_list_policies`, `plugins_search_plugins`, `tagging_create_tag`, `tagging_add_tags_assets`, `agent_groups_list`, `agent_restart_agent`, `agent_update_agent`, `credentials_list_managed_credentials`, `audit_log_get_audit_log_events`, `dashboard_create_dashboard_from_template`, `ticket_create_issue`.

Bank risk:

- **Your findings and asset data go to the AI provider you connect.** Tenable's own page says region and retention depend on that provider.
- "Confirm before each write" is a behaviour of the AI client, not a server control. The real control is the role on the API key.
- Claude Desktop setup uses the community `mcp-remote` package, which one listing author found writes the API key header to its log.
- Hexa is on by default. An administrator can turn it off or restrict it through custom roles.

**Recommendation: leave it out of the migration.** If it is enabled later, use a dedicated read-only custom role and an approved model endpoint. The `curb` listing is a sound way to work out the minimum role.

## 5. CyberAgents Exchange: what it is and how far to trust it

- **Size:** 146 listings: 28 agents, 81 skills, 29 MCP servers, 8 playbooks. The website and the GitHub repo match exactly. No website-only listings.
- **It is a directory, not a code host.** Each listing links to the author's own repository. The code can change after review.
- **Contributed tier (142):** secret scan, licence check and a read-through by two Tenable staff. Tenable's own wording: it "does not constitute a comprehensive security audit".
- **Vetted tier (4):** deeper review tied to one commit. The four are CyberAgents Exchange Submit, Remediation Priority & Impact Agent, SOC-Hunter and Splunk Tenable Cloud Security Skill. **None helps this migration.** The vetted Submit skill tells the agent to overwrite itself from the author's GitHub, so the reviewed commit is not what runs after an update.
- **Tenable One filter:** 19 listings. All need Tenable One and Hexa.
- **Age:** the first listing is dated 2026-05-28. Nothing here has more than six months of track record on the Exchange.
- **"Skill" often means a prompt file.** Many skills contain no code. "Read-only" is then an instruction to the AI, not something enforced.
- **Listings are not always accurate.** Examples found in code: a listing licensed MIT whose repo is AGPL-3.0 (SentinelOne), a "no external calls" claim that loads Google Fonts, a "read-only" calendar skill that calls a write tool on every scan, and a "CIS/STIG/PCI" skill whose config says CIS only.

### Listings that can write to Tenable (27)

Community MCP Server for Tenable, Exception Guardian, Export Nessus Template, Exposure Response Consultant, Navi, Nessus Agent Companion, PCI ASV Scan Copilot, Porygon Mitigator, Reconcile Stale Scan Agents, Supercharged Tenable Identity Exposure MCP Server, T1OTE IEC 62443 Onboarding, Targeted Nessus Scan, Tenable + SentinelOne Asset Reconciliation, Tenable Identity Exposure MCP Server, Tenable MSSP Portal MCP Server, Tenable OT MCP Server (Enterprise Manager Edition), Tenable OT Security MCP Server, Tenable SC AI Analyst, Tenable SC Health Check, Tenable SC Reporting Assistant, Tenable Tag Optimizer, Tenable.sc MCP Server, The Hounds — Artifact, The Hounds — Pack Playbook, The Hounds — navi-agents, navi-mcp, navi-skills.

Worst cases for a bank:

- **Tenable.sc MCP Server:** any GET/POST/PUT/PATCH/DELETE on any Security Center endpoint, and its Docker setup publishes the service on all interfaces with no authentication.
- **Tenable Identity Exposure MCP servers:** raw write passthrough, including creating API keys and deleting users.
- **navi-mcp and The Hounds:** with two environment flags set, an AI agent can delete assets, rotate API keys and run shell commands on hosts over SSH.
- **Tenable SC AI Analyst and Tenable SC Health Check:** TLS certificate checking is off by default.

## 8. How this was done, and its limits

- Cloned `tenable/cyberagents-exchange` and every one of the 144 distinct linked repositories (two listings share one SentinelOne repository).
- Each listing and its linked README were read, and the code was searched for write calls, outbound hosts, credential storage, tests and licence files. Six AI reader passes did this in parallel; I spot-checked the top picks myself.
- One reader noted that the longest READMEs in its batch were read in part and verified by targeted code search rather than line by line.
- Nothing was executed, so behaviour is inferred from code, not observed.
- Clones were shallow, so commit counts and contributor numbers are not known.
- The Hexa tool list comes from documentation and from names used in listings. I had no tenant to enumerate it.
- The org list came from GitHub search (76 repositories plus 13 forks). Private repositories are not visible.
- Author type is inferred from handles, licence files and README text where the listing does not state it.

**Most important point: plan the migration around pyTenable and your own scripts. Treat the Exchange as a reference shelf, and decide SaaS versus Security Center before shortlisting anything else.**
